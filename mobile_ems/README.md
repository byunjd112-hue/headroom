# IFPS 이동형 전력체계 EMS (노트북 실장비 연동판)

군 이동형 마이크로그리드(PV·디젤·수소 연료전지·ESS)를 **노트북 한 대에서** 실장비와 Modbus TCP로 연동해 감시·제어하는 EMS입니다.
외부 CDN·클라우드 없이 폐쇄망에서 동작하며, 의존성은 Python 3.10+ 와 numpy 하나뿐입니다.

| 구성 | 위치 | 기능 |
|---|---|---|
| 핵심 프로그램 `ifps_ems` v0.6.0 | `ifps_ems/` | 부하·PV 24h 예측, 동적계획법 운전계획, N-1 예비력, 통신 감시·지령 판단, 연쇄 HMAC 감사 기록 (통신 모듈 없음) |
| 실장치 연동 계층 `ifps_ems_rt` v0.1.0 | `ifps_ems_rt/` | Modbus TCP(이중 경로 A/B), 대응표, SBO 지령·응답 확인·대체 전원, 1초 실행기 |
| 제어화면(HMI) + 디버그 도구 | `ifps_ems_rt/hmi/` | 웹 제어화면(브라우저), 경보 관리, 추세, 통신 진단, 레지스터 탐색기, 프레임 추적, 고장 주입 |
| 현장 간편 진단 도구 | `ifps_ems_rt/diag.py`, `diag.bat`, `diag.sh` | 번호 차림표. 장비·경로별 7단계 자동 진단(원인·조치 안내, 순서·자료형·배율 추정), 실시간 감시, 주소 탐색, 지령 규약 시험, HTML 보고서 |
| 현장 점검 CLI | `ifps_ems_rt/mbtool.py` | probe / read / watch / write / check |

## 빠른 시작
**Windows 노트북**: `run_sim.bat` 더블클릭 → 브라우저가 열리고 가상 장치로 전체 기능 시연.
**실장치**: `config/runtime.json`의 장치 IP(경로 A·B)·unit과 `config/pointmap.csv`의 레지스터 주소를 제작사 자료로 맞춘 뒤 `run_live.bat`. 자료형은 16비트(u16·i16)·32비트(u32·i32·f32)·64비트(u64·i64·f64), 바이트 순서는 `pointmap.csv`의 `order` 열 또는 `runtime.json`의 `devices.<장비>.order`에 ABCD/CDAB/BADC/DCBA로 적는다. 순서 판별은 `python -m ifps_ems_rt.mbtool read <IP> -a <주소> -n 4 --orders`. 상세는 `docs/out/이동형전력체계EMS_실장치통신연동방안서_Rev00.pdf`.

```
pip install -r requirements.txt
python -m ifps_ems verify                                          # 자가 점검
python -m ifps_ems gen-sample results/sample_site_data.csv         # (실측 이력 전) 합성 자료
python -m ifps_ems train results/sample_site_data.csv results      # 예측 모델 학습
python -m ifps_ems_rt.hmi config/runtime.json --sim --plan results --open   # 가상 장치
python -m ifps_ems_rt.hmi config/runtime.json --plan results --open         # 실장치
python -m unittest discover -s tests                               # 시험 107건
diag.bat --demo                                                    # 현장 진단 도구 연습(가상 장치) · 실장비는 diag.bat
```
제어화면: http://127.0.0.1:8080 · 기본 PIN 운용자 `1111`, 엔지니어 `2222`(개발 모드 전용). 운용 모드(`run_mode: "운용"`)는 평문·기본 PIN, 외부 바인드, 가상 장치를 기동 단계에서 거부한다 — `python -m ifps_ems_rt.hmi.pin`으로 해시를 만들어 `pin_operator_hash`/`pin_engineer_hash`에 넣는다

## 제어화면
- **개요**: 발광 헥사곤 단선 결선도와 실시간 전력 흐름 애니메이션, 수급·SOC 눈금 게이지·ESS 상태, 연료/수소 잔량과 운전 가능 시간, N-1 예비력, 자동 제어 상태
- **작전지 배치 편집**(개요 → [배치 편집], 운용자 권한): 장비 대수·막사 수량 추가/복제/삭제, 끌어서 위치 이동, 이름·연결 급전선(1~3등급) 지정. 배전 케이블(FSU 환상망·인입·통신선)은 배치에서 자동 생성되고 실시간 통전·고장 상태가 반영된다. 저장 시 `state/layout.json`(이전본 `.bak`)과 감사 기록에 남는다
- **설비 제어**: IFPS ①~⑥ 체계 구성 기준 8개 설비 카드(① 복합전력 디젤·ESS, ② 이동형 ESS, ③ PV(계통 연결·분리·출력 제한), ④ 연료전지·수전해, ⑤ EMS, ⑥ 배전·계측 게이트웨이), ⑥ 차단기 9개 상태와 2·3등급 부하 차단·복구(SBO), 배치 기준 설비 수량.
  기존 설명: 선택-실행(SBO) 2단계 지령(10초 제한), 연동 조건(두절·수동·중복·잠금) 사전 차단, FC 출력 설정, AUTO/MANUAL 전환, 지령 기록
- **경보**: ISA-18.2 형식 4단계 우선순위, 발생/복귀/확인, 경보 이력, 감사 기록 무결성 검증
- **추세**: 1초 표본 4시간, 5분~4시간 창, CSV 내보내기 · **통신 진단**: 장치×경로 RTT/오류율, 수집 주기 분포, 워치독
- **디버그**: 레지스터 탐색기(FC01~04 읽기, U16/I16/U32/F32 동시 해석, 직접 IP 접속), 레지스터 쓰기(엔지니어), Modbus 프레임 추적(HEX·MBAP/PDU 해석·저장), 포인트 맵 실시간 값/품질, 가상 장치 고장 주입(무응답·지령 무시·수동 모드·경로 단절·시나리오), 시스템 정보
- 화면 색: 주간(올리브·흑녹·카키, 육군 디지털 전투복 계열) / 야간(MIL-STD-3009 NVIS 취지의 저휘도 청록) / 네이비. 메뉴는 계측·제어·관리로 구분
- KO/EN 전환, DTG(Zulu) 시각, 서버 응답 없음 화면 경고

## 장비 이미지
- **실사 스프라이트**(`static/sprites/*.webp`, 투명 배경·등각 시점, 11종 772KB): 작전지 배치도와 단선결선도 타일에 사용. 운전 상태는 필터로 표시(정지·개방 = 채도·밝기 낮춤, 트립·두절 = 적색 착색), 배치 편집 그대로 가능
- **실사 사진**(`static/photos/*.jpg`, 11종): 설비 제어·발전·예측의 장비 카드에 사용
- 두 이미지는 AI(Higgsfield)로 장비 묘사 텍스트만 입력해 생성(제안서 이미지 미사용). 파일이 없으면 자체 벡터 일러스트로 자동 대체. 실물 사진이 생기면 같은 이름으로 교체

## 보안·신뢰성
- 접속은 사설·루프백 주소의 허용 목록만(공인 주소·DNS 이름 거부), HMI 기본 바인드 127.0.0.1, CSP·토큰 권한(조회/운용자/엔지니어)
- 모든 로그인·지령·레지스터 쓰기·고장 주입을 연쇄 HMAC 감사 기록에 남김. 운용 모드는 검증필 암호모듈이 아니면 기동 거부
- 전 장치·경로 병렬 수집: 응답 없는 장치가 있어도 주기 초과 없음. 지령 응답 대기는 별도 스레드라 수집을 막지 않음
- systemd `Type=notify` + `WatchdogSec`: 수집·제어가 모두 살아 있을 때만 감시 신호 (`service/ifps-ems.service`)

## 군 운용 기능 (작전지·주둔지 겸용, Rev18~)
- **운용 장소**: 작전지(자립 운전) / 주둔지(상전 연계). 설비 제어 화면에서 전환하며 재기동해도 유지된다(`state/ops.json`)
- **주둔지 운전**: 상전 + ESS 로 운전하고 디젤·연료전지는 정지. **역송 없음**(최소 수전 유지, 남는 태양광은 ESS 충전 → 수전해 → PV 출력 제한 순), **요금 절감**(최대부하 시간대 ESS 방전, 경부하 시간대 충전, 피크 억제), **정전 대비**(충전율 하한 `reserve_soc` 아래로는 방전하지 않음). 수전 차단기가 열리면 곧바로 자립 운전 논리로 넘어가고, 복전 후 `restore_s` 초 안정하면 복귀. 설정은 `runtime.json` 의 `garrison`
- **운용 태세**: 평시 / 저소음(디젤 금지·연료전지 허용·3등급 자동 차단) / 자립(목표 시간 `autonomy_target_h` 를 버티도록 부하 단계 관리)
- **부하 우선순위 자동 차단·복구**: 자원 부족을 3초 지속 확인 후 3등급 → 2등급 순 차단, 해소 60초 뒤 역순 복구. 1등급은 차단하지 않음. EMS 가 끊은 급전선만 되살림
- **자립 지속시간**: ESS·수소·연료와 하루 태양광 예상량으로 전 부하 / 3등급 차단 / 1등급만 기준 남은 시간 표시
- 추가 점: `GRID.kw`, `CB.GRID`, `FLT.GRID`(계측·보호 게이트웨이), `ESS.kw_set`(PCS 충·방전 지령). 설비 정격을 체계 제안서 값으로 정렬(디젤 90kW, 수전해 150kW, 수소 저장 하한 30%)
- 무정전 절체 자체는 ESS(계통 형성)와 STS 가 수행한다. EMS 는 판정·전원 투입·부하 관리를 맡는다. GFM 드룹 조정과 블랙스타트 절차는 PCS 인터페이스 확정 후 구현 대상

## Rev16 보완 요약
- **독립 검토 2회**(통신·서버, 화면)로 찾은 결함 42건 보완. 주요: 생존 계수 정지 장비로 자동 지령이 나가던 문제, 감사 기록 쓰기 실패 시 주기 스레드 종료, 형식이 틀린 응답에 전 장비 수집 중단, NaN 값에 화면 정지, 로그인 없이 가능한 변경 경로, 탭 화면 잘림. 목록은 `docs/out/…SW신뢰성시험결과서` 7장
- **실장비에 맞춘 통신**: 정의되지 않은 주소를 건너뛰는 묶음 읽기(`devices.<장비>.gap`), 순번·지령 한 프레임 쓰기, 수용(seq_ack)·완료(status) 분리와 장비별 완료 한도(`devices.<장비>.done_s`). 가상 장치도 없는 주소에 예외 02를 낸다
- **실측 이력 8일 미만이면 실장치는 규칙 운전**(합성 자료 계획은 `--sim` 시연에서만)
- 감사 기록: 쓸 때마다 디스크 반영, 잘린 끝줄 격리, 8MB에서 파일 넘김(연쇄 유지)
- 시험 81건, 문장·분기 실행률과 소스코드 메트릭은 `python tools/static_report.py`

## 태양광 예측 보강 — 하늘 카메라와 주의집중 예측 (Rev30)

- **하늘 카메라**: 카메라(또는 카메라 PC)가 최신 하늘 사진(PNG)을 `runtime.json` 의 `skycam.path`(비우면 `state/skycam.png`)에 계속 덮어쓰면, EMS 가 10초마다 읽어 구름량(0~100%)을 구하고 15분 이력의 `sky` 열에 남긴다. 사진이 없거나 3분 넘게 오래됐거나 밤이면 값을 비우고, 낮에는 경보를 낸다 — 예측은 발전 실적·기온·기압·습도만으로 계속한다. 가상 장치 모드는 하늘 그림을 스스로 만들어 같은 경로로 흘려보낸다.
- **주의집중(어텐션) 예측**: 지금과 닮은 과거 상황을 찾아 그 뒤에 실제로 나온 발전을 가중 평균한다(대형 언어 모델의 핵심 연산과 같은 원리, 규모는 아주 작음). 선행시간 구간마다 검증에서 오차가 줄어드는 비율만큼만 기존 예측에 섞는다. 발전·예측 화면의 태양광 예측 아래에 구름량, 섞는 비율, 가장 닮은 과거 시점이 보인다.
- 효과(합성 자료, `python docs/ppt/pv_ai_eval.py`): 2시간 이내 오차가 8~38% 줄고 24시간 전체는 0~8% 준다. 실제 효과는 현장 카메라 자료로 다시 확인해야 한다.

## 운영 시나리오 — 시퀀스·구성도 보기 (Rev34~35)

- 운영 시나리오 화면에서 **시퀀스 / 구성도** 두 보기를 오간다. 구성도는 장비 사진 블록, 배전반(모선 A·B), 차단기 12개를 입체로 놓고 단계마다 지령·응답과 전력 흐름을 보여 준다.
- 단계 표시줄의 번호를 누르거나 ▶ 재생으로 넘긴다. 검증을 실행한 뒤에는 차단기 상태(투입·개방·트립), 장비 출력과 운전 상태가 단계마다 바뀐다.
- 블록을 누르면 그 장비·차단기의 신호로 단계를 바로 넣는다. 블록을 끌면 배치가 바뀌고 이 브라우저에 저장된다(배치 초기화 버튼).
- 장비 사진은 `ifps_ems_rt/hmi/static/photos/` 의 파일을 쓴다. 실물 사진으로 바꾸려면 같은 이름으로 교체한다.

## 시나리오용 추가 설비와 보호 협조 (Rev36)

- 구성도 보기의 **설비 구성** 버튼(엔지니어)으로 대응표에 아직 없는 급전선·차단기, 변압기, 보호 계전기를 가상 장치에 추가한다. 정의는 `config/scenario_extra.json` 한 파일에 저장되고 실제 대응표(pointmap.csv)는 바뀌지 않는다.
- 보호 계전기는 정한시 과전류다: 감시하는 급전선들의 전력 합이 정정값을 정한 시간 동안 넘으면 차단기를 트립시키고 고장 코드를 남긴다. 하위 차단기가 먼저 열리면 그 부하가 상위 감시에서 빠지므로 선택 차단을 시험할 수 있다.
- 기본으로 수전 변압기 1대(1,000 kVA 가정)와 과전류 계전기 4개가 들어 있고, 보호 협조 기본 시나리오 3건이 있다. 정정값은 시험용 가정값이다.

## 보호 요소 확장 · 수급 반영 · 실시간 구성도 (Rev37)

- 보호 계전기 요소: 과전류(kW), 지락(A — 시나리오에서 `GF.<급전선>` 으로 넣음), 부족전압(V — 모선 A·B). 시간 특성은 정한시 또는 IEC 반한시(표준·강·초, 배율 지정).
- 차단 실패 후비: 계전기에 후비 차단기와 시간을 주면, 트립을 냈는데 차단기가 열리지 않을 때(`STK.<차단기>` = 1 로 모사) 후비 차단기가 고장 코드 50 으로 트립한다.
- 추가 급전선의 "EMS 수급 반영"을 켜면 그 전력이 EMS 가 보는 부하 합계에 더해지거나(부하) 빠진다(전원). 사진도 고를 수 있다.
- **실시간** 보기: 지금 장치에서 읽은 값으로 구성도를 그린다. 실장비 모드에서도 열리며 표시 전용이다(지령 없음). 값이 없는 신호는 "값 없음"으로 보인다.

## 기록 보관 · 운영 보고서 · 기록 조회기 (Rev38)

- **기록 보관소** `state/archive.db`(SQLite 한 파일): 저장 주기마다 구간 전력량·구간 최대·평균 상태·**검침 누적값**을 한 줄씩 쌓고, 사건·경보(상황 기록)와 사람이 넣는 점검 기록(절연저항·접지저항 등)을 함께 둔다.
- 설정 `runtime.json` 의 `archive`: `interval_min`(1·5·15·30·60분, 기본 15), `retain_years`(1~5년, 기본 4), `max_mb`(기본 2048), `server_url`(주둔지 서버 주소, 비우면 수동 전달), `outbox`(묶음 폴더). 보관 기간이 지난 줄은 자동 삭제, 한도를 넘으면 가장 오래된 달부터 삭제한다.
- 근거: 점검 결과 기록 보존 기간 4년(전기안전관리법 시행규칙). 운전 자료의 저장 주기를 정한 조항은 확인하지 못해 검침 관행인 15분을 기본으로 했다 — 현장 지침이 있으면 그 값으로 바꾼다.
- 화면 **기록·보고서**: 시간별·일별·월별·연도별 조회(줄을 누르면 아래 단위로), 상황 기록 글자 찾기, 점검 기록 입력, 보관 상태, CSV 내려받기, **보고서 출력(Word)**.
- 보고서 차례: 현재 현황 · 최근 운영 현황 · 상황 기록 · 운전 시퀀스(태세별 동작, 지령 기록, 시나리오 단계와 검증 결과) · 전기안전 점검 기록(검침 누적값 포함) · 자료 보관 상태.
- **기록 조회기**(읽기 전용, EMS 를 켜지 않고): `viewer.bat` / `./viewer.sh` 또는 `python -m ifps_ems_rt.archview <archive.db>`.
- 가상 장치 모드는 첫 기동 때 합성 과거 자료 400일치를 넣는다(화면·보고서에 * 표시). 누적 지침은 EMS 적산값이라 정산용 계량기와 다를 수 있다.
- **ESS 안전 운영정보**: 전기안전공사 ESS 통합관리시스템이 받는 운영정보(운영 환경 · 배터리 · PCS · 보호 이벤트)를 같은 주기(1분)로 현장에 쌓는다. 항목은 `config/ess_safety.csv`(key, group, label, unit, tag). tag 가 빈 항목은 0 으로 적고 "미수집"으로 표시한다. 공사의 정식 항목 명세는 확보하지 못해 공개된 분류에 맞춘 초안이다.
- **장치별 자료**: 대응표의 읽기 신호를 장치(디젤 · 연료전지 · 태양광 · ESS · 수소 · 주둔지 발전기 · 수전해 · 모선 …)별로 저장 주기마다 평균 · 최소 · 최대로 쌓고 화면에서 찾아본다.
- **주둔지 서버 전달**: 화면의 '서버 전달'에서 구간 묶음(zip: manifest · ess_safety.csv · meter.csv · events.csv · inspect.csv · device_*.csv)을 만들고, 서버로 올리거나(`server_url`) 보조 기억 매체로 옮긴 뒤 완료를 적는다. 이력에 구간 · 줄 수 · SHA-256 · 방법 · 시각 · 담당이 남는다. 받는 쪽 참조 프로그램: `python -m ifps_ems_rt.archrecv <폴더> [--bind] [--port]`.

## 시나리오 분류 · 고장 대응 시나리오 · 고르기 창 (Rev42)

- 기본 시나리오 36건을 네 분류로 나눴다: 정상 운전 · 운전 모드 12, 정상 운전 · 장비 시퀀스 6, **고장 대응 (FMEA) 12**, 보호 협조 (FAT 시험 항목) 6. 시나리오마다 `cat`(분류), `ref`(FMEA 번호), `fat`(실장비 시험에서 확인할 것 — FMEA 의 검증 방법)이 있다.

## 환망 단선 대응 · FMEA–시나리오–FAT 연결 (Rev43)

- **환망(고리 모양 배전) 모형** `hmi/scenring.py`: 전원 ─ S1 ─ N1 ─ S2 ─ N2 ─ S3(상시 개방점) ─ N3 ─ S4 ─ 전원. 구간 단선(`BRK.<구간>`) → 구간 차단(`RING.<구간>` = 2) → 상시 개방점 투입 → 전 마디 재공급(`RN.<마디>`, `RING.ok`). 정의는 `config/scenario_extra.json` 의 `ring`. 가상 장치에만 생긴다.

- **FMEA·FTA 워크벤치의 '시나리오·FAT 연결'**: 고장모드 63건마다 확인 수단(운영 시나리오 19 · 회귀 시험 9 · 실장비 시험·절차 35), 연결된 시나리오와 결과, FAT 확인 항목. Excel 시트 `20_시나리오·FAT연결`.
- 통신 두절·센서 오류·노트북 고장처럼 검증기 단계로 만들 수 없는 고장모드는 시나리오가 없고 회귀 시험·실장비 시험으로 확인한다(워크벤치 표에 그렇게 나온다).

## 날씨 입력 · 군 통신망 날씨 반영 (Rev46)

- **무엇**: 장병이 휴대폰 날씨 앱(구글 날씨 등)에서 본 내용 — 날씨 표기(맑음·대체로 흐림·비 …)·강수 확률·기온·기간 — (작전지, 수기 입력. 운량 같은 전문 값은 묻지 않고 표로 환산한다)와 군 통신망의 날씨 자료(주둔지)를 태양광 예측에 섞는다. 계산 `ifps_ems_rt/weather.py`, 화면부 `hmi/weatherwatch.py`, 화면 `static/weather.js`(발전·예측 화면 아래 패널), 설정 `runtime.json` 의 `weather`.
- **날씨 기반 예측** = 맑은 하늘 발전량 × 구름 계수(1 − 0.75·(운량/10)^3.4, Kasten·Czeplak 1980) × 설비 보정(최근 14일 맑은 때의 실측 비율).
- **AI 예측과 비교**: 최종 = (1 − w_h)·AI + w_h·날씨 기반. 예측을 낼 때마다 1·3·6·12시간 뒤 값을 적어 두었다가 낮 시간 실측과 견주어, 선행시간 묶음 h 마다 실측에 가장 잘 맞았을 비율 w_h = Σ(실측 − AI)(날씨 − AI) ÷ Σ(날씨 − AI)²(0~0.8)로 정한다. 쌓이기 전에는 0.3. 날씨 기록이 없는 시간은 AI 예측 그대로.
- **표기별 배우기**: 넣은 날씨 표기가 실제로 맑은 하늘의 몇 배 발전으로 이어졌는지 실측으로 모아 환산값을 그 현장의 값으로 고친다(`Score.factor`).
- **효과(측정)**: 합성 자료로 잰 효과(설비 용량 대비 평균 절대 오차, 날씨 기록이 있는 낮 시간): 수기 입력 3.9 → 3.59%(7.9% 감소), 통신망 3.96 → 3.16%(20.2% 감소). 6~24시간 앞에서 크다(수기 4.28 → 3.9%, 통신망 4.31 → 3.42%). 1시간 이내는 AI 가 이미 정확해 수기 입력에서는 1.76 → 1.85% 로 조금 나빠졌다. 앱 · 통신망 예보의 오차 크기는 가정이며 현장에서 다시 확인해야 한다(python docs/ppt/wx_eval.py).
- **우선순위**: 겹치면 손으로 넣은 것이 통신망 자료보다 먼저. 반영 대상은 화면의 태양광 예측, 자립 지속시간의 하루 태양광 예상량, 예측 기반 운전계획(`PlanPolicy.pv_adjust`).
- **통신망 받기**: `weather.url`(http·https 만, 요청으로 받지 않음)에서 `interval_min` 마다, 기본은 주둔지에서만. 실패해도 경보 없이 직전 자료와 AI 예측으로 운전. 주소를 쓸 수 없으면 화면에 JSON·CSV 를 붙여 넣는다. 가상 장치 모드의 시험용 자료는 `/api/archive/weather_sample`.
- 한계: 통신망 자료 형식은 가정(실제 군 기상 체계에 맞춰야 함). 기온·강수는 기록만 하고 부하 예측은 그대로. 효과 수치는 합성 자료와 가정한 예보 오차에서 얻은 것이라 현장 수치가 아니다.
- **통합 점검 도구** `python -m tools.soak_check`: 가상 장치에 단선·겹친 단선·장비 이동·교체·추가·트립·통신 두절·충전율 저하·부하 급증을 차례로 넣고 경보·대응·1등급 부하 공급 유지를 찍는다(약 5분).

## 환망 감시 · 장치 자동 인식 · 휴대용 배전체계(PPDU-20) 구성 (Rev44)

- **전력 흐름**: ⑥ 배전체계 → 구간분전함(FSU, 야전 구간분전함 · 환상 간선) → 휴대용 배전체계(PPDU-20, 20 kW) → 분기 6회로 → 시설 부하. PPDU 제원은 PPDU-20 상세기술자료(정격 20 kW, 주 차단기 40 A, CH1·CH2 3상 16 A 10.5 kW, CH3~CH6 단상 20 A 4.4 kW, CH2 는 환상 연결용, 접지저항 100 Ω 인터록, 환상 연결 5초 이내 우회)를 따랐다.
- **장치 자동 인식(조작 없음)**: 작전지마다 장치를 놓는 자리와 대수가 달라지므로 EMS 가 배치를 스스로 알아낸다(`ring.layout`). 자리(FSU1‥7, PPDU1‥8 — 통신 순서 = 고리 순서)마다 읽은 ID 가 곧 그 자리의 장치다. 이름·회로 구성은 ID 를 따라가고, ID 0 인 자리는 화면·경보에서 빠지며, 처음 보는 ID 는 새 장치로 바로 들어간다. 배전체계가 물린 구간분전함은 `PPDUk.up`(상위 ID)으로 안다. 같은 ID 가 둘이거나 종류가 다른 장치일 때만 3등급 '확인 필요' 경보. `runtime.json` 의 `ring.auto` 를 거짓으로 하면 예전처럼 고정 배치와 비교한다.
- **주 장치 자동 인식**(`ifps_ems_rt/fleet.py`, `hmi/autodev.py`, Rev45): 같은 종류 장치를 여러 대 놓아도 스스로 알아낸다. `runtime.json` 의 `devices` 에 `DG2`·`FC2`·`ESS2`·`PV2` 같은 추가 자리를 두면(대응표는 첫 장치의 줄을 본뜬다) 응답하는 장치만 '있는 장치'로 삼아, 종류 이름의 값(`DG.kw`, `ESS.soc` …)을 합·평균으로 바꿔 넣고, 기동·정지는 모두에게, kW 설정값은 똑같이 나누어 보낸다. 빈 추가 자리는 경보 없이 10초마다만 다시 불러 본다. 켠 뒤 한 번도 응답하지 않은 종류는 '미설치'(3등급 알림)로 보고 디젤 ↔ 연료전지를 서로 대신한다. 응답하던 장치가 끊기면 평소대로 1등급 통신 두절. 개요 배치도·결선도·제어·통신 화면이 인식한 대수대로 스스로 다시 짜인다. 한계: 같은 종류는 정격이 같고 같은 급전 차단기 아래라고 본다(순차 기동·비례 분담 없음), 운전계획은 한 대분 정격으로 계산, 수전해·주둔지 발전기는 한 대 기준.
- **대응표 적용**: 신호 175개를 `config/pointmap.csv`(계측·배전 게이트웨이 MTR, 주소 200~382)에 넣었다 — `RING.sw0`·`RING.auto`, `FSUk.id/.v/.sw`, `PPDUk.id/.up/.v/.kw/.mccb/.gnd/.lamp/.ch1~6/.ch1_kw~6_kw`. EMS 가 1초마다 읽어 감시하고 기록 보관소의 장치별 자료에도 쌓인다.
- **환망 화면**(`hmi/static/ring.js`): 구성도, FSU 표, PPDU 표(줄을 누르면 6회로). 경보: 구간 차단, 상시 개방점 닫힘, 무전압, PPDU 주 차단기·회로 트립(회로 등급대로), 과부하(20 kW 초과), 접지저항 초과, ID 확인 필요, 연결 미확인. 계산은 `ifps_ems_rt/ring.py`, 화면부 연결은 `hmi/ringwatch.py`.
- **복구 절차(Rev47)**: 가상 장치에서 단선을 풀면(고치면) 차단됐던 구간을 다시 잇고 상시 개방점을 다시 열어 평소 상태로 돌아온다(`ring.Model._repair`) — 구간을 하나씩 끊었다 풀며 연습할 수 있다.
- **EMS 전원 · 통신선(Rev47)**: 개요 배치도에 구간분전함의 EMS 통신선과 EMS 전원 이중화(배전 모선 · 차량 28 V · 무정전 전원 — 하드웨어 설계)를 표시. 모선이 죽으면 `ems.power` 경보(무정전 전원으로 운전 중 — 모선 전압으로 추정, `autodev.ems_power`).
- **환망 구조(Rev47 확정)**: 양쪽 급전(모선 A → 첫 구간분전함, 모선 B → 마지막 구간분전함). 복귀선 한 줄 구조(급전 1곳)는 급전 구간이 끊기면 전체가 정전되어 쓰지 않는다(사용자 결정).
- **화면 연동 점검(Rev47)**: `node tools/link_check.js` — 가상 장치에 상황 25건(구간 0~7 단선 · 해제, 겹친 단선, 구간분전함 빼기 · 뒤섞기, 장치 추가 · 제거)을 넣고 개요 · 결선도 · 환망 · 설비 제어 · 경보 화면이 같은 상태를 보이는지 화면 글자로 대조한다. 운영 시나리오의 실시간 보기에는 자동 인식 대수가 나오고(구성도 · 실시간 보기에 환망 그림은 두지 않는다 — 사용자 요청), 인식되지 않은 둘째 장치(DG2 …)는 장비 목록에서 빠진다.
- **화면 배치 점검(Rev48)**: `node tools/layout_check.js` — 모든 화면 · 탭 · 도움말 각 절에서 내용이 잘리는데 스크롤이 없는 곳, 표 머리가 틈을 두고 붙는 곳, 화면 오류를 찾는다.
- **장치 대수 조정(Rev49)**: 설비 제어 화면의 − · ＋(`hmi/unitctl.py`, `POST /api/units`). 가상 장치는 놓고 빼고, 실장비는 빈 자리를 바로 다시 찾거나 철수한 장치를 인식 목록에서 지운다. 추가 자리는 디젤 · ESS · 연료전지 4대, 태양광 5대까지(`config/runtime.json` 의 devices — 주소는 가정). 개요 배치도는 같은 종류가 늘면 그림을 줄여 첫 장비 뒤로 겹쳐 세우고(`layScale` · `layStack`, Rev50), 배치 편집에 들어가면 그 장치를 끌어 옮겨 저장할 수 있다(`layAdopt`). 인식된 대수보다 많이 놓은 그림은 '예비 자리'로 흐리게 보인다.
- **장치 구성 변화 대응(Rev50)**: ① 시나리오 — 모의 신호 `UNIT.<장치>`(`hmi/scenunit.py`)로 장치를 놓고 빼며 검증, 기본안 '장치 구성 · …' 6건(전체 51건, 한 번에 64건까지). ② FMEA — `ES-10 장치 구성 변화` 7건(FM-52 ~ FM-58), 시나리오의 `ref` · `fat` 과 연결. ③ 기록 · 보고 — 있는 장치의 값만 장치별 자료에 저장(`Fleet.clean`), 추가 장치는 '디젤발전기 2'처럼 따로 표시, 보고서 1.5절 '장치 구성'.
- **차량 단위 대수(Rev51)**: ① 복합전력 차량 = 디젤 + 계통 형성 ESS(G1) — 디젤 대수가 늘면 형성 용량도 대수만큼(`runtime.g1_n` · `g1_kw`, G1 은 통신이 없어 디젤 대수로 미루어 봄). ④ 수소 차량 = 연료전지 + 수전해 — 어느 쪽에서 눌러도 함께 늘고 준다(`unitctl.MATE`, 수전해 추가 자리 ELZ2~4). 태양광 차량 그림은 패널이 차량 뒤로 펼쳐지는 형상으로 교체(AI 생성 그림). FMEA FM-59 · FM-60, 시나리오 '수소 차량 2대' 추가(전체 52건). 시나리오 구성도의 블록에 놓인 대수 표시.
- **복합전력 PCS(Rev52)**: 기동형 복합전력공급체계는 발전기 + ESS 를 PCS 가 묶은 한 제품이다. FMEA FM-60~62, 시나리오 '복합전력 · …' 3건.
- **통신선 환형(Rev52)**: 개요 배치도의 통신선을 전력 케이블과 같은 경로로(구간분전함은 환형). `ring.status` 가 구간분전함마다 통신 도달(`comm`)을 계산하고 두 구간 단선으로 고립되면 `ring.comm.<장치>` 경보. 환형 통신 장치는 설계 제안(FMEA C-13).
- **복합전력 PCS 설정 편집(Rev53)**: 디버그 화면 → 설정 편집 → '복합전력 PCS' 탭(엔지니어)에서 모드 값 · 이름(`hybrid.modes` · `labels`), 충전율 한계값, 신호 주소(대응표의 `DG.pcs_mode` · `ess_soc` · `ess_kw` · `mode_set`)를 고친다. 실행기 · 가상 장치 · 화면이 모두 설정의 값을 쓴다(`hybrid.settings` · `Plant.set_hybrid` · 스냅샷 `kpi.hy`). 계측 합계 범위는 빈 자리가 있으면 한 대분 여유(`Fleet.span`).
- **지령이 계획 계산을 기다리지 않게(Rev53)**: 24시간 운전계획(동적계획법)을 뒤에서 계산한다(`planlink.PlanPolicy.background`). 계산하는 동안 자동 제어는 직전 계획 또는 규칙 운전으로 판단하고, 운용자 지령(선택 · 실행)은 바로 처리된다. EMS 를 멈추면 뒤에서 돌던 예측 · 계획 계산도 중단한다. 수치 계산은 한 가닥으로 묶는다(`OPENBLAS_NUM_THREADS=1`).
- **모듈 정리(Rev54)**: 제어화면 엔진 한 파일(997줄)을 뼈대 `hmi/engine.py` 와 기능별 묶음(`eng_alarms` 경보 판정 · `eng_command` 지령 · 자동 제어 · `eng_auth` 인증 · `eng_view` 화면 자료 · `eng_forecast` 예측 · 학습 · `eng_tools` 엔지니어 도구), 공용 `engdefs` · `alarmmgr` · `simdriver` 로 나눴다(동작 동일). 파일을 안전하게 바꿔 쓰는 코드는 `ifps_ems_rt/fsio.py` 하나로 모았다.
- **실전 대비 보완(Rev54)**: ① 정지 지령 실패가 다른 전원의 정지로 번지지 않게(대체는 기동 실패 때만). ② 읽기가 길어져도 살아 있는 장치를 두절로 보지 않음(응답 시각 = 읽기 완료 때, 요청 · 장치별 시간 한도). ③ ESS 충전율을 못 읽으면 안전 쪽으로 발전기 기동(`soc.blind`), 수전 차단기 상태를 못 읽으면 판정 유지 · 기동 정지 보류(`grid.blind`). ④ 이력 쓰기 실패가 빠른 제어 · 경보를 멈추지 않음(`hist`). ⑤ 돌아온 장치에 설정값 다시 쓰기, 현장 수동 장치에는 설정값을 쓰지 않음. ⑥ 자동 제어 켬/끔 · 인식한 장치 · EMS 가 끊은 급전선을 재기동 뒤에도 이어 감(`state/ops.json` · `seen.json`). ⑦ '없는 주소' 응답은 그 블록만 빼고 읽음(`part.<장치>`). ⑧ 여러 대 가운데 한 대를 못 읽은 주기에는 직전 합계 유지. ⑨ 복합전력 PCS 경보(`hy.mode` 모드 불일치 · `hy.soc` ESS 저충전 · `hy.unknown` 모르는 모드 값). ⑩ 설정 검사: 허용 대역 밖 주소, 수집 주기 · 응답 한도 범위, 완료 한도(`done_s`) 주의. ⑪ 앞선 지령에 밀려 늦어진 운용자 지령은 버림. FMEA `ES-11`(FM-63~69).
- **남은 한계 보완(Rev55)**: ① 지령 완료 한도 — 지령을 받아들인 장치는 공통 한도(`done_s`, 기본 20초)까지 상태 변화를 기다린다(장치별 값이 없어도 느린 기동을 실패로 보지 않는다). 걸린 시간은 시스템 정보의 '지령 완료 시간'에 남는다. ② 수전점 계측 두절 중 정전 추정 — ESS 가 설정값보다 훨씬 많이 내보내는 상태가 20초 이어지면 정전으로 보고 자립 논리로(`runtime._blind_outage`, PCS 동작 가정). ③ 가상 자료 가져오기 · 재생 — 디버그 → 가상 장치 탭에서 CSV(초 또는 시각 + 신호 열, history.csv 도 가능)를 1~600배속으로 가상 장치에 넣는다(`hmi/simreplay.py`, `static/simreplay.js`). ④ 사용자 설명서에 '값을 읽지 못할 때', '재기동 뒤 이어 가는 것', '지령 완료 한도', '가상 자료 재생', '시간 설정 범위'를 넣음. ⑤ 끊긴 브라우저 접속이 기록에 예외로 남지 않게.
- **부하 관리(Rev55)**: '부하 관리' 화면에서 부하의 종류 · 수량 · 등급 · 대당 정격 · 절감 비율을 늘리고 줄인다(`ifps_ems_rt/loads.py`, `hmi/loadctl.py`, `static/loads.js`, `POST /api/loads`, 상태 파일 `state/loads.json`). 목록은 스냅샷의 `loads` 로 나가 개요 배치도(수량만큼 그림 · 겹쳐 세움 · 빠진 그림은 예비 자리), 결선도(등급별 개수 · 정격 · 절감 표시), 환망, 운영 시나리오 구성도, 설비 제어의 차단기 이름, 보고서(1.6 부하 구성)에 함께 반영된다. EMS 가 재는 것은 급전선(등급)별 합계이므로 부하별 전력은 정격 비율로 나눈 추정값이다. 등급별 정격 합은 그 급전선의 계측 범위(대응표)를 넘을 수 없다.
- **절감 공급 후 차단(Rev55)**: 공급 능력이 부하를 따라가지 못하면 3등급 절감 공급 → 3등급 차단 → 2등급 절감 공급 → 2등급 차단 순서로 내려간다(`opsmode.LoadShedder` 의 `save` 단계, 지령 값 `LDS.L2 · L3 = 3`, 절감 뒤 10초 지켜봄). 덜어 낸 부하를 되살리면 다시 모자랄 때는 되살리지 않는다(`held` · `_keep`). 태세 · 충전율 사유는 바로 차단. 절감 지령을 받아 부하를 줄이는 부하 쪽 장치는 가정이다(없으면 절감 비율 0 → 바로 차단). 시나리오 '부하 관리 · …' 3건, FMEA FM-70~72. C++ 판에는 절감 단계가 없다(차단 · 복구의 동등성은 유지).
- **분기 전력계 · 분기별 부하 예측(Rev56)**: 구간분전함(FSU) · 휴대용 배전체계(PPDU) · PPDU 6회로의 분기 전력계를 대응표에 넣었다 — `FSUk.kw` · `FSUk.kwh`, `PPDUk.kwh`, `PPDUk.chN_kwh`(주소 383~515, 전력량은 u32 · 0.01 kWh. 주소 · 배율은 가정). 환망 화면의 '분기별 전력 · 전력량 · 부하 예측' 표가 분기마다 지금 kW · 오늘/누적 kWh · 다음 1시간 · 24시간 예측 · 최대 예상 시각 · 1시간 앞 오차를 보인다. 예측은 `ifps_ems_rt/branchfc.py`(15분 구간 평균 → 시간대 평균의 지수 가중 → 최근 1시간 수준 보정), 자료는 `state/branch.json`. 구간분전함 전력계와 아래 배전체계 합이 어긋나면 `ring.meter.<FSU>` 경보. 전체 부하 예측(AI)과 운전계획은 바꾸지 않았다. FMEA FM-73.
- **부하 ↔ 배전체계 연결(Rev58)**: 부하마다 '물린 배전체계'가 있다(`loads.attach` — 종류에 따라 자동, [고치기]에서 지정). 개요 배치도는 부하 그림을 종류로 짝지어(등급을 바꿔도 같은 그림이 그 부하다) 그 배전체계의 구간분전함으로 케이블을 잇고, 결선도는 배전체계 아래에 그 부하들의 이름 · 그림 · 추정 전력을 그린다 — 두 화면과 부하 관리가 같은 부하 · 같은 값을 보인다. 부하 목록의 정격과 PPDU-20 정격(20 kW)은 따로 관리하므로 추정 전력과 배전체계 전력계 값은 다를 수 있다.
- **배치 편집 — 크기 · 미세 이동(Rev59)**: 개요의 [배치 편집]에서 모든 그림(장비 · 부하 · 구간분전함)의 크기를 40~160% 로 바꾸고(`s`, 배치와 함께 저장), 방향키로 1칸(Shift 10칸 · Alt 0.2칸)씩 옮긴다. 이동 범위 제한을 넓혔다.
- **모선 구성(Rev59)**: 전원 · 부하 급전선의 모선 소속(A · B)을 [모선 구성](개요 · 결선도, 엔지니어)에서 바꾼다 — `ifps_ems_rt/busplan.py`(점검 `check` · 자동 보완 `auto` · 모선 전압 `live`), `hmi/busctl.py`(`POST /api/bus`, `state/bus.json`), `static/busplan.js`. 결선도 · 운영 시나리오 구성도 · 가상 장치(시나리오 검증 포함)가 같은 구성을 쓰고, 같은 모선 안의 좌우 순서는 개요 배치도를 따른다. 점검: 모선마다 계통 형성 전원, 1등급 부하 모선의 전원, 모선별 정격, 전원 쏠림. 정전으로 이어질 약점은 `bus.plan` 경보. 이 구성은 실제 결선을 알려 주는 값이다(화면에서 바꿔도 케이블은 옮겨지지 않는다). FMEA FM-74.
- **부하 ↔ 화면 연동(Rev59)**: 부하의 자리는 '물린 구간분전함' 하나가 기준이다(`loads.attach`). 개요 [배치 편집]에서 부하 그림을 옮겨 저장하면 가장 가까운 구간분전함으로, 이름을 고치면 목록의 이름으로 반영된다(`POST /api/loads {op: "place"}`). 결선도 · 환망 · 설비 제어 · 발전·예측 · 추세 · 시나리오가 같은 목록(`LD`)을 쓴다. 예비 자리는 '부하 없음'으로 표시하고, 겹치는 표지는 떼어 놓는다. 점검: `node tools/load_link_check.js`.
- **공급 경로(Rev60)**: 구간분전함(FSU — AC 380 V · 630 A · 출력 4회로, 제안 발표 자료의 사양. kW 비교는 역률 0.9 가정으로 약 374 kW) → 배전체계(PPDU-20, 20 kW, 부하 바로 앞) → 부하. 부하 하나가 20 kW 보다 크면 배전체계를 병렬로 여러 대 붙인다(`loads.need`). 자리 · 대수 계산은 `loads.spots` · `attach` · `plan`, 가상 장치는 부하 목록대로 배전체계를 놓고(`ring.Model.want`) 분기 전력계를 만든다(`ring.Model.branch`). 환망 구성도 · 결선도 · 개요 · 부하 관리(공급 경로) · 기록 보고서가 같은 경로를 보인다. ★(중요 부하)는 1등급 부하가 물린 자리. 따로 이름을 붙이지 않은 배전체계는 앞의 부하 이름으로 부른다. 경보: 구간분전함 과부하 `ring.over.FSUk`. 가상 장치의 배전체계 자리는 8개다. 점검: `node tools/load_link_check.js`.
- **상시 개방점**: PPDU-20 자료의 설치 절차('환상망 구성은 상시개방점(NOP) 1개소를 반드시 유지 — 순환 전류 방지')를 그대로 따른다. 닫힌 고리 운용(구간마다 방향성 보호 필요)은 넣지 않았다.
- **다른 화면과의 연동(Rev46)**: 환망의 차단 구간 · 정전 마디 · 장치 이름이 개요 배치도(놓인 자리를 따라 고리 순서로 잇는 케이블 `fsuRing`, 붉은 ✕, 구간분전함 이름표, 배전체계 표지, 이상 개소), 결선도 그림 안의 환망 고리(`sld.js` 의 `sldRing` — 모선과 부하 사이: 모선 A · B → 환망 → 배전체계 → 등급별 회로 → 부하. 부하는 구간분전함 바로 아래에 실선으로 단다(끊긴 구간이 있어도 반대쪽 공급으로 살아 있는 것이 보인다). 등급별 합계는 맨 아래 한 줄. 고리의 양 끝은 모선 A 와 모선 B 에 물린다), 설비 제어의 구간 개폐기 표(감시 전용), 운영 보고서 1.4절(`report._ring`)에 같은 이름으로 나온다.
- **초기 기동 점검**: 자동 인식 결과를 전원에서 가까운 순서로 보여 주는 창(인식 · 비어 있음 · 무응답 · 확인 필요). 눌러야 인식되는 것이 아니다.
- **배전체계 구성 · 중요 부하**(운용자): 6회로마다 물린 시설과 부하 등급(1·2·3, 환상 연결·미사용), 상시 개방점. 화면의 ★(중요 부하)와 정전 경보 등급은 부하 관리의 1등급 부하가 물린 자리를 따른다(Rev60 — 부하 목록이 비어 있을 때만 회로 등급 설정). 구성은 장치 ID 에 묶여 `runtime.json` 의 `ring` 에 저장되므로 다른 자리에 놓아도 따라간다.
- 가상 장치 모드에서는 환망 모형이 같이 돌고, 엔지니어가 구간 단선 · 자동 절체 끄기 · 배치 뒤섞기 · 장치 빼기/넣기 · PPDU 주 차단기/회로 트립 · 접지 불량을 넣어 연습한다.
- 가정과 아직 넣지 않은 것: 자리 순서 = 통신 순서, ID 윗자리로 종류를 가리는 체계(0x46 FSU · 0x50 PPDU), 상위 ID 신호 `PPDUk.up`, FSU·PPDU 자리 수·주소는 가정값이다(실제 장치 사양이 정해지면 맞춘다). PPDU 끼리 CH2 로 잇는 환상 연결, PPDU 의 무선(메시·LTE) 통신 방식, 4중 보호협조의 무선 블로킹은 넣지 않았다.
